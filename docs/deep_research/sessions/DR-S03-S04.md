## 5. 必须冻结的架构决策

### 5.1 新旧隔离

未来实现默认使用新命名空间：

```text
src/litflow/deep_research/
```

原则：

- 冻结 MVP 与 M8 不直接改造成新 Runtime；
- 通过 adapter/wrapper 复用已验证函数；
- 新 Schema、状态和 artifact 均带独立版本；
- 新输出只进入 `outputs/deep_research_v1/`；
- 不覆盖旧 corpus、qrels、QA、writing 或 M8 trace。

本轮只写文档，不创建该源码目录或 output 目录。

### 5.2 四层架构

必须冻结为：

1. **Domain Contracts**：Pydantic/纯Python定义任务、来源、证据、claim、citation、状态和结果；
2. **Deterministic Kernel**：身份、hash、预算、transition guard、grounding、coverage、终止与safe failure；
3. **Orchestration Adapter**：LangGraph负责节点调度、checkpoint集成和条件路由，但不拥有证据身份或最终展示权；
4. **Provider/Tool Adapters**：LLM、local retrieval、未来Web/VLM均通过可替换接口接入。

现有 durable events、BM25、span mapper、QA validation 作为 `wrap/reuse` 候选；文档必须引用 S01 的路径和证据，不得写成已经接入新 Runtime。

### 5.3 控制流

冻结逻辑阶段，不在本轮确定最终 enum 名称：

```text
brief → approval → plan → research → evidence check
      → bounded replan（可选）→ write → validate
      → complete / insufficient_evidence / failed / cancelled
```

必须明确：

- 人工未批准 Brief 时不得真实执行；
- replan 有次数、token、tool-call 与wall-time上限；
- Writer保持单一；
- Validator失败不能通过模型自评绕过；
- 所有终态必须有结构化结果或失败 artifact；
- Multi-Agent 未来只能替换 Research Executor，不重写Evidence Kernel和Writer。

### 5.4 数据与上下文边界

- Source/Evidence/Claim/Citation identity 由程序生成；
- 模型只返回候选计划、查询、claim、关系或修复建议；
- Evidence Store 保存完整原始证据与provenance；
- Model Context View只是按预算选取的视图，不是事实存储；
- 文本、未来Web和未来page+bbox多模态证据共享同一上层身份合同；
- S05/S06 才定义精确字段，本轮不得伪造已实现 Schema。

### 5.5 初始持久化

- S05–S20 初期以版本化JSON/JSONL、原子写入和append-only events为主；
- 复用/包装既有durable event思想；
- SQLite持久化留到S39，除非后续真实证据证明文件合同无法满足并发/恢复；
- 不因参考项目使用SQLite就提前引入数据库。

## 6. 参考模式取舍矩阵

必须对以下模式逐项给出：`observed_problem`、`current_evidence`、`decision`、`admission_gate`、`default_path`。

允许的 decision：

```text
adopt_now
reuse_or_wrap_now
defer_until_evidence
reject_for_default_path
conditional_experiment
```

### 6.1 默认建议（必须用仓库证据复核）

| 候选模式 | 初始决策 | 理由 |
| --- | --- | --- |
| LangGraph 单Agent编排 | reuse_or_wrap_now | 已有依赖与M8经验，但Evidence Kernel必须独立 |
| 显式生命周期状态 | adopt_now | M8失败与恢复需要可判定阶段；具体enum留S07 |
| append-only durable events/replay | reuse_or_wrap_now | 已有fake replay证据，需新合同包装 |
| Research Brief人工确认 | adopt_now | 防止开放问题无界执行 |
| Evidence Gap + bounded replan | adopt_now | 解决缺证据，不等于无限自循环 |
| 单一Writer | adopt_now | 避免多Agent合写重复和结构破碎 |
| asyncio + Semaphore | defer_until_evidence | 只有并行任务与provider限制出现后才有收益 |
| Supervisor + Research Workers | conditional_experiment | 必须等Single-Agent held-out基线后等预算消融 |
| Red–Blue/Critic | defer_until_evidence | 先从真实错误构建taxonomy，不能凭角色想象 |
| L1/L2/L3上下文压缩 | defer_until_evidence | S36需验证evidence recall和token收益 |
| 跨Agent共享记忆 | reject_for_default_path | 初期用共享Evidence Store，不把对话记忆当事实 |
| SQLite/vector memory | defer_until_evidence | 文件artifact优先，S39/S44再按需求引入 |
| 多provider热切换 | defer_until_evidence | 先冻结transport contract；不为简历堆provider |
| page+bbox多模态证据 | conditional_experiment | 是差异化重点，但需S42–S47 text-only消融 |

如果 Codex 建议改变任一默认决策，必须给出具体代码/测试/artifact证据；不能只说“业界常见”。

## 7. 实验与数据治理冻结

### 7.1 数据分层

冻结概念：

- `fake`：确定性状态、失败和replay测试；
- `canary`：极小真实任务，用于transport/grounding故障发现，不用于最终性能宣称；
- `dev`：允许诊断和一次次改进；
- `heldout`：冻结前不可查看结果，不用于Prompt/阈值/Schema调参；
- `public_benchmark`：外部可比结果，必须单独报告数据许可和adapter。

S04只冻结治理原则，不创建未来benchmark题目。

### 7.2 Run identity

未来每次真实run至少记录：

```text
run_id
schema_version
git_commit_sha
worktree_status / dirty policy
task/input identity and hashes
provider/model/resolved mode
prompt/template hashes
tool and retriever versions
budgets and retry policy
start/end timestamps
artifact contract version
```

API key、完整环境变量值、私人绝对路径不得落盘。

### 7.3 Artifact合同

冻结建议布局：

```text
outputs/deep_research_v1/runs/<run_id>/
├── run_manifest.json
├── brief.json
├── plan.json
├── events.jsonl
├── checkpoints/
├── sources.jsonl
├── evidence.jsonl
├── claims.jsonl
├── report.json
├── metrics.json
└── failure.json（仅失败时）
```

本轮不创建output；精确Schema在S05–S10实现时版本化。

### 7.4 指标层

冻结类别而非伪造结果：

- task：grounded completion、safe abstention、execution failure；
- claim：coverage、support/contradiction、unsupported leakage；
- citation：membership、quote/span/region grounding；
- trajectory：steps、replan、retry、cache、resume/replay；
- efficiency：provider calls、tokens、wall time、cost；
- human：pass/minor/major/reject；
- LLM-as-Judge：只能作为补充，不能替代deterministic grounding与人审。

### 7.5 外部调用审批

- S05–S18 默认Fake/offline；
- 真实LLM canary必须等Gate A，并获得provider、model、task数、最大预算授权；
- Web必须等Gate B；
- heldout必须先冻结manifest、数据hash、配置和阈值；
- 多模态/Multi-Agent/Critic必须预注册对照组和保留门槛；
- 失败不得覆盖，retry必须计入成本。
